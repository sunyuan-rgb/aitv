## 各阶段分工

| 阶段 | AI 完成 | 学生完成 |
| --- | --- | --- |
| 需求与约束 | 读取题面/规范，起草 `AGENTS.md`、需求说明、假设清单、原型、任务清单 | 确认实现范围（单部剧、6 集、演示播放、SQLite），确认 A1-A10 假设，要求"不得伪造编号" |
| 方案与建模 | 设计剧集状态机（草稿/待审/通过/上架/停售/暂停）、修订表、购买-权益-退款模型 | 审阅状态机与"价格上架后固定""每集最多一份待审修订"等取舍 |
| 编码 | 编写 store/content/sales/billing/refund/web 全部 Go 代码、SQLite schema、9 个页面与 API | 逐提交检查 diff；发现目录接口泄露草稿字段并要求改 DTO |
| 测试 | 编写 7 个包单元测试（含 4 个并发用例），修复 12 处首轮失败，补齐错误分支至 86.6% | 要求"覆盖率达标但不许删测试/排除代码"；核对原始输出 |
| Skill | 用 skill-creator 初始化并编写两个 Skill 的脚本与清单 | 指定"两个 Skill 自己用"，审阅 Skill 触发条件与失败处理 |
| Git/PR | 按规范拆分 10+ 提交、创建 PR #1-#4、合并并核对 main CI | 提供仓库与分支策略；核查提交消息格式与编号说明 |
| 部署/验收 | 编写 CI、Dockerfile、部署冒烟脚本；执行本地部署与验收 Skill | 审阅 CI 失败原因，要求"必须真修复后重跑"，确认验收结论与证据位置 |

## 学生实际审核的内容

1. 全部提交的 `git diff` 与提交类型是否单一（feat/fix/test/docs/opt 不混用）。
2. `AGENTS.md` 的关键约束是否落到代码：事务原子性、条件扣币、幂等 request_id、自审拦截、越权拦截。
3. 测试是否真实覆盖业务规则（逐条对照题面 R1-R8 查看断言，而非只看覆盖率数字）。
4. 失败与修复记录：gofmt、CI 冒烟、目录字段泄露三项是否真实修复而非绕过。
5. 验收报告与 Skill 调用输出是否为真实命令结果（对照 `docs/testing/` 原始文件）。
