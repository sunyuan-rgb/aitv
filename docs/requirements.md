# 需求说明 — 题目 04：短剧内容上架、付费观看与下架处理

> 原始题面：《Go项目业务场景题.md》题目 04。本文件为学生的需求分析产出，题面为准。

## 1. 业务背景

短剧平台将剧集内容交给运营编辑整理，经内容审核后对用户开放。前 2 集免费试看，后 4 集按集付费（各 100 平台币）。用户购买的是**指定剧集的单集观看权益**。平台需同时管理：

- 内容是否可用（上架/暂停观看）
- 内容是否允许销售（在售/停止销售）
- 用户已取得的权益（购买/退款撤销）

## 2. 参与角色

| 角色 | 关键操作 | 关键约束 |
| --- | --- | --- |
| 内容编辑 | 维护剧集资料、提交审核、修改后重新提交 | 不得自行审核自己提交的内容 |
| 审核人员 | 通过/退回（说明退回原因） | 审核通过才能首次上架；已上架内容修改须重新审核 |
| 运营 | 上架、停止销售、暂停观看/恢复，查看影响范围 | 操作必须填写原因；下架不得抹掉购买记录 |
| 用户 | 浏览、试看、购买、观看、查询消费记录 | 只能访问自己的权益与消费记录 |
| 客服 | 核查付费用户在暂停观看后的退款申请 | 只退一次，撤销对应权益；免费集无退款 |

预置：1 部 6 集短剧（第 1-2 集免费、第 3-6 集付费各 100 币）；预置用户余额（如用户 u1=500 币）；不实现充值。播放用演示地址。

## 3. 状态模型

### 3.1 剧集（Episode）状态

```text
草稿(draft) --编辑提交审核--> 待审(pending_review)
待审 --审核通过--> 已审核(approved)
待审 --审核退回--> 退回(rejected)  [可修改后重新提交]
已审核 --运营上架--> 已上架(published)
已上架 --运营暂停观看--> 暂停观看(paused)      [禁止购买+播放，含已购用户]
已上架 --运营停止销售--> 停止销售(sales_stopped) [禁止新购买，已购可观看]
```

内容生命周期与销售状态分离：
- `paused`：购买 ✗ 播放 ✗（对所有人）
- `sales_stopped`：购买 ✗ 播放 ✓（已购用户）
- `published`：购买 ✓（付费集）/ 播放 ✓

### 3.2 待审修订（未公开修订）

已上架内容修改 → 生成待审修订（每集最多 1 份），不直接替换已发布展示版本；修订审核通过后需运营重新发布才生效。

### 3.3 权益与退款

- 权益（Entitlement）：用户×剧集唯一；仅付费集需购买产生；状态 `active` / `refunded`。
- 退款申请（RefundRequest）：仅**付费集 + 已购用户**在**暂停观看期间**可发起；状态 `pending` / `approved` / `rejected`；同一用户同一集只能有一次 `pending/approved`，只退一次。

## 4. 业务规则（对应题面 8 条）

1. 编辑维护标题、集序、免费/付费、播放地址，提交审核；仅审核通过可首次上架；退回后可修改重提。
2. 已上架内容任何修改 → 重新审核（未公开修订，不替换已发布版本）；每集最多一份待审修订。
3. 用户仅能浏览已上架内容；免费集直接取得播放信息；付费集购买成功后产生单集权益。
4. 价格首次上架后固定；持有效权益重复购买不重复扣币（返回已有权益）；退款撤销权益后再次购买形成新购买记录；并发购买不同集不能使余额为负；扣币与权益同事务原子生效。
5. 停止销售仅禁新购，已购可看；暂停观看同时禁购买与播放（含已购）；操作须填原因并展示给受影响用户。
6. 暂停期间已购用户可申请退原扣平台币；客服确认后只退一次并撤销权益；免费集/未购用户不得申请。
7. 恢复可用后：未退款已购用户恢复观看；已退款用户旧权益不可用但可重新购买（新购买记录）；历史购买与退款记录全部保留。
8. 运营可查每集状态、购买人数、待处理退款；客服可解释用户为何能看/不能看；用户只能看自己的消费记录。

## 5. 验收条件（可验证）

1. 完整场景「发布与消费」：编辑提交 → 审核退回 → 修改重提 → 通过 → 上架 → 用户试看第 1 集 → 购买第 3 集 → 播放成功。
2. 完整场景「停售分支」：停止销售后新用户购买被拒、老用户播放成功、恢复销售后新用户可购。
3. 完整场景「暂停分支」：暂停 → 已购用户播放被拒 → 申请退款 → 客服批准 → 余额退回 + 权益撤销 → 恢复内容 → 已退款用户不能看、可重新购买；未退款用户直接恢复观看。
4. 并发验证：重复购买不重复扣币；余额只够一集时并发买两集恰成功一集且余额不为负；购买与停售并发结果一致。
5. 权限验证：编辑自审被拒；越权访问他人消费记录被拒；免费集申请退款被拒；未购用户申请退款被拒。
6. 覆盖率 ≥85%（整体与核心包）；`go vet` / `gofmt` / `-race` 通过。

## 6. 边界（不做）

转码、推荐、会员、版权采购、真实视频分发、充值、多部剧管理（固定一部剧）。
