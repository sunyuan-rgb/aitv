# 短剧业务一致性检查（题目 04）

## 用途

对短剧平台数据库执行确定性核查，验证题面 8 条业务规则在数据层面的一致性：

1. 只有审核通过的内容可上架（规则1）
2. 已上架内容的修订须审核通过后才可发布；每集最多一份待审修订（规则2）
3. 付费集购买必有购买记录 + 有效权益，扣币与权益一一对应（规则3/4）
4. 权益持有人重复购买不产生第二次扣币（规则4）
5. 任何用户余额不为负（规则4）
6. 暂停观看的集：无新增购买、退款单只退一次（规则5/6）
7. 已退款权益不可再用；重新购买形成新购买记录（规则7）
8. 购买、退款、操作留痕历史完整（规则8）

## 触发场景

- 内容上架/停售/暂停/恢复、购买扣币、退款处理相关代码变更后
- 验收前、部署后冒烟时
- 用户报告"扣了币不能看"等咨询需核查时

## 输入

- `--db`：SQLite 数据库路径（默认 `data/aitv.db`）。必须先停止服务或接受只读瞬时快照（WAL 模式下可并发读）。

## 执行步骤

1. 运行核查脚本：

   ```bash
   python skills/short-drama-consistency-check/scripts/check_consistency.py --db data/aitv.db
   ```

2. 脚本依次执行 `scripts/checks.sql` 中带编号的核查项，每项输出 PASS/FAIL 与证据行。
3. 对 FAIL 项：定位对应业务代码（internal/billing、internal/refund、internal/sales），
   向学生报告问题与建议修复位置；**不得直接修改业务数据**。

## 输出格式

```text
[CHECK 1] 审核通过才可上架 ............ PASS (6/6)
[CHECK 4] 无重复扣币 .................. FAIL
  证据: user_id=1 episode_id=3 purchase_count=2 balance_deducted=200
结论: 2 FAIL / 6 PASS
```

## 失败处理

- 脚本无法连接数据库：提示确认 `--db` 路径与服务是否占用文件锁，不要伪造结果。
- 某项核查 SQL 出错：跳过该项并标注 `SKIP(原因)`，结论中说明覆盖不完整。
- 存在 FAIL：结论必须为"业务一致性未通过"，并列出修复建议；修复后重跑脚本复测。

## 完成标准

所有核查项 PASS 且无 SKIP；输出留存在验收/核查记录中作为证据。
